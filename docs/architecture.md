# 宿主与模块架构

LazyBuddy是Windows x64的Tauri/Svelte桌面宿主。前端资源嵌入EXE，WebView2负责界面和浏览器视频呈现；宿主通过Rust桥调用独立服务，不加载任意脚本插件或业务源码。

## 仓库所有权

| 仓库 | 负责内容 |
| --- | --- |
| [LazyBuddy](https://github.com/LazyBuddyDev/LazyBuddy) | 界面、窗口/托盘/热键、通用设置、模块与应用更新管理、CLI、API调度 |
| [news-service](https://github.com/LazyBuddyDev/news-service) | 新闻来源、解析、偏好、缓存及独立API |
| [hongguo-service](https://github.com/LazyBuddyDev/hongguo-service) | 账号、搜索、官方收藏、观看进度、取源与受控浏览器媒体资源 |
| [reader-service](https://github.com/LazyBuddyDev/reader-service) | 本地书库、TXT/EPUB解析、正文和图片、阅读偏好及位置；书籍、来源与内容版本分离 |

宿主源码位于`apps/desktop`，通用Rust组件位于`crates`；具体归位见[文件放置规范](file-layout.md)。新业务的独立API可以被其他前端使用；接入当前宿主仍需实现相应受信页面与调度，不能仅靠清单声明自动执行任意界面。

## 安装与调用

基础宿主不包含业务服务或Python、Go、GStreamer。模块管理器从可信目录验签，核对ZIP哈希、大小、路径、目标平台与精确依赖后，准备整组不可变版本目录并原子激活注册表。

开发版与安装版通过同一Windows用户的公共模块目录复用已安装功能和运行时。服务客户端按清单启动包内入口，拥有其进程树，使用私有JSON Lines会话。宿主不通过工作区相对路径寻找服务实现或构建SDK。包与进程约定见[模块契约](module-api.md)。

## 页面与生命周期

宿主提醒由前端`attention.ts`的来源注册、稳定事件修订、目标聚合与快照确认组成，公共标记为`AttentionDot.svelte`。新来源通过`AttentionCenter.register`取得发布/注销入口，发布/注销自动通过注册中心的变更回调更新展示快照，也可使用`items()`读取当前快照；调用方不直接改其他来源状态。注销后旧发布者不能覆盖重新注册的来源。已读凭据归宿主设置，后台保存与其他宿主设置共用有序写入；确认不执行来源的业务操作。公共消除与外观约束见[UI规范](ui-guidelines.md#提醒标记)。

首期来源为可信功能目录中的未安装能力及已安装能力的新版本，以及已准备好的应用更新。目录从宿主启动及每15分钟按签名配置核对，不安装包、不派发内容请求；下载不持有设置/退出操作锁，失败保留内存中的已验证目录。隔离实例禁用该自动联网检查。首次启用时未安装且未确认的能力显示一次提醒；同一能力确认后不因未安装而重复提醒。模块更新以可用版本标识，应用更新以版本和构建标识区分同版本新构建。已读凭据最多保留2048项确认，达到上限后会截断已存凭据；被回收的事件再次出现时可能重新提醒。未来大规模来源需按实际需求调整容量和回收策略。

根页面、功能页和设置页共用窗口外壳；功能页与设置页平级，关闭后回当前根页面。齿轮只打开全局设置；各内容页通过独立设置页签调整所属偏好。全局设置归宿主，内容偏好、业务缓存、账号及媒体归所属独立服务；仅由宿主绘制的局部外观偏好沿用宿主持久化，但只应用于所属内容。外观与公共交互统一遵循[UI规范](ui-guidelines.md)。

同时最多一个可见根页面工作。切页和隐藏停止页面派发，取消在途任务并用激活代数隔离迟到回复；聚合数据最多四个实际在途来源。托盘、热键及应用更新独立于内容静默。

媒体服务输出短期、受控的本机压缩媒体资源，浏览器负责解码、同步和实际帧时间，不通过JavaScript逐帧传像素。隐藏时暂停并卸载`video.src`、停止资源读取；恢复不自动播放。离开页面释放所属会话，旧会话不能覆盖新播放进度。

## 状态与信任

全局配置有序、原子保存，退出等待必要收尾。读取失败时用临时默认值进入只读运行，保留原文件；成功落盘才确认设置修改，快捷键预应用失败时恢复原值。生产实例沿用已验收的安全存储scope和数据位置；隔离测试使用独立目录与身份空间，不导出或复制凭据。收藏的乐观反馈与官方确认分开，失败或取消回滚。

模块目录与应用更新是两套签名入口；安装成功、账号恢复和真实节目权限分别验证。发布与验证步骤见[模块分发](module-distribution.md)、[应用更新](app-updates.md)和[定向测试](testing.md)。当前未完成任务及其交付边界只在[TASKS](../TASKS.md)维护，完成后删除，不设任务归档。
